2. Freie Funktionen

Freie Funktionen werden ohne umgebende Klasse (deswegen: frei) deklariert - im Gegensatz dazu die Element-Funktionen.

Die erste freie Funktion ist main():

Quelltext 1. Zeilen aus der Datei ppc0501.cc 
1int main() { (1)
2}
1 main() ist auch eine freie Funktion!
Warum freie Funktionen?

Ein wichtiges Grundprinzip in der Sprache C++ ist die Gleichbehandlung von primitiven und selbstdefinierten Datentypen (UDT). Objekte selbstdefinierter Typen werden auch als first-class-Objekte bezeichnet, d.h. sie enthalten nicht nur strukturierte Daten sondern auch Operationen (Elementfunktionen, Methoden).

Die primitiven Datentypen in C++ ergeben keine first-class-Objekte. Man kann daher keine Elementfunktionen für primitive DT aufrufen.

Dies ist bei der generischen Programmierung (in C++ template⁠s genannt) sehr wichtig, denn man möchte Code unabhängig vom Typ - insbesondere der Unterscheidung zwischen primitiven und nicht-primitiven Typen - schreiben. Das spiegelt sich auch in der Einführung der Operator-Überladung wieder.

2.1. Definition eigener freier Funktionen

Wir definieren eine Funktion double quadrat(double):

Quelltext 2. Zeilen aus der Datei ppc0502.cc 
 1#include <iostream>
 2double quadrat(const double value) { (1)
 3    return value * value;
 4}
 5int main() {
 6    const double x{42.42};
 7    std::cout << "Quadrat von " << x << " ist "
 8              << quadrat(x) (2)
 9              << std::endl;
10}
1 Definition der freien Funktion quadrat()
2 Aufruf der freien Funktion quadrat()
Um ein Symbol in C++ verwenden zu können, muss es zuvor deklariert worden sein, denn der Compiler traversiert den Quelltext nur einmal von oben nach unten. Weil aber jede Definition zugleich auch eine Deklaration ist, kann ppc0502.cc kompiliert werden.

Wir erhalten die Ausgabe:

Ausgabe 1. Ausgabe des Programms: ppc0502
Quadrat von 42.42 ist 1799.46
Bislang hatten wir solche Funktionen in der Klasse Math als statische Elementfunktionen (Klassenmethoden) untergebracht.

Es kann vorkommen, dass zwei Funktionen sich wechselseitig aufrufen. Um das Henne-Ei-Problem bei der Definition der beiden Funktionen zu lösen, kann man wie bei Elementfunktionen die Deklaration von der Definition trennen.

Hier die getrennte Deklaration und abgesetzte Definition der Funktion double distance(const Point&, const Point&) zur Berechnung der Distanz zwischen den geometrischen Punkten:

Quelltext 3. Zeilen aus der Datei ppc0503.cc 
 1#include "../ppc.h"
 2#include "point40.h"
 3#include <iostream>
 4#include <cmath> (1)
 5double distance(const Point& a, const Point& b); (2)
 6int main() {
 7    Point p1{1.0, 1.0};
 8    Point p2{2.0, 2.0};
 9    std::cout << "Distanz: " << distance(p1, p2) << std::endl; (3)
10}
11double distance(const Point& a, const Point& b) { (4)
12    const double dx{a.getX() - b.getX()};
13    const double dy{a.getY() - b.getY()};
14    return std::hypot(dx, dy); (5)
15}
1 Notwendig für die Verwendung von mathematischen Funktionen wie std::hypot() oder std::sqrt()
2 Deklaration der Funktion distance(), wird auch Prototyp genannt
3 Aufruf der Funktion distance()
4 Definition der Funktion entsprechend obiger Deklaration
5 Berechnung der Hypotenusen-Länge
Ausgabe 2. Ausgabe des Programms: ppc0503
Distanz: 1.41421
Mathematische Funktionen der C++-Standardbibliothek
Die C++-Standardbibliothek enthält eine Vielzahl mathematische Funktionen, darunter auch std::sqrt oder std::hypot (s.a. Hypotenuse).

2.2. Module und Codestrukturierung

Grundsätzlich können Deklarationen und Definition ohne Einschränkungen in Übersetzungseinheiten strukturiert werden, solange folgende Regeln eingehalten werden:

  • Jeder Bezeichner muss vor seiner Verwendung deklariert worden sein.

  • Für jeden Bezeichner darf es nur eine Definition geben (One Definition Rule, ODR)

Darüberhinaus empfiehlt es sich selbstverständlich, Klassen und dazugehörige freie Funktionen zusammenzufassen.

Der Code in main() hat sich nicht geändert:

Quelltext 4. Zeilen aus der Datei ppc0504.cc [Snippet: points] 
1const Point p1{1.0, 1.0};
2const Point p2{2.0, 2.0};
3std::cout << "Distanz p1-p2: " << distance(p1, p2) << std::endl;

Allerdings gehört die freie Funktion double distance(const Point&, const Point&) zur Klasse Point. Denn Sie ist ausschließlich auf Parameter des Datentyps Point anwendbar. Sie sollte deswegen in der Headerdatei point41.h deklariert und in der Implementiersungsdatei point41.cc definiert werden:

Quelltext 5. Zeilen aus der Datei point41.h [Snippet: distance] 
1double distance(const Point&, const Point&); (1)
1 Deklaration einer freien Funktion der öffentlichen Schnittstelle der Klasse Point
Quelltext 6. Zeilen aus der Datei point41.cc [Snippet: distance] 
 1double distance(const Point& a, const Point& b) { (1)
 2    const double dx{a.getX() - b.getX()};
 3    const double dy{a.getY() - b.getY()};
 4    return std::hypot(dx, dy);
 5}
 6SIMPLETEST("Point distance") { (2)
 7    Point p1 = {0.0, 0.0};
 8    Point p2 = {1.0, 1.0};
 9    if (!Math::equal(distance(p1, p1), 0.0)) return false;
10    if (!Math::equal(distance(p2, p2), 0.0)) return false;
11    if (!Math::equal(distance(p1, p2), std::sqrt(2.0))) return false;
12    return true;
13};
1 Defintion der freien Funktion
2 Auch die freie Funktion muss getestet werden!
Freie Funktionen, die in ihren Parameterlisten nur einen UDT verwenden, gehören zu der öffentlichen Schnittstelle dieses Typs. Daher werden sie sinnvollerweise und üblicherweise in der zugehörigen Headerdatei des Typs (Klasse) deklariert und in der Implementiersungsdatei definiert (s.a. Abschnitt 3.1).

Typumwandlungskonstruktor

Typumwandlungskonstruktoren sind allgemeine Konstruktoren, die mit einem Parameter eines anderen Typs aufgerufen werden können. Bei Parameterlisten mit Arität > 1 müssen die weiteren Parameter Vorgabewerte besitzen.

Die Rolle des Typumwandlungskonstruktors kann durch das Schlüsselwort explicit abgeschaltet werden.

Das folgende, einfachere Beispiel macht das nochmals deutlich:

Quelltext 9. Die Klasse A mit Typumwandlungskonstruktor
1class A {
2public:
3    A(const int v) : mValue{v} {} (1)
4private:
5    int mValue{0};
6};
1 Dies ist ein allg. Konstruktor in der Rolle eines Typumwandlungskonstruktors
Quelltext 10. Die Klasse B ohne Typumwandlungskonstruktor
1class B {
2public:
3    explicit B(const int v) : mValue{v} {} (1)
4private:
5    int mValue{0};
6};
1 Implizite Typumwandlung durch das Schlüsselwort explicit ausgeschlossen
Quelltext 11. Zeilen aus der Datei ppc0511.cc [Snippet: conversion] 
1A a1{1}; (1)
2A a2 = 2; (2)
3a1 = 3; (3)
4a2 = 4;
5B b1{1}; (4)
6//    B b2 = 2; (5)
7//    b1 = 3;
8b1 = B(3); (6)
1 Verwendung des allgemeinen Konstruktors
2 Der int-Initialisierer 2 wird in ein temporäres, anonymes Objekt des Typs A konvertiert und damit wird a2 kopier-initialisiert
3 Der int-Wert 3 wird in ein temporäres, anonymes Objekt des Typs A konvertiert und dieses wir dann an a1 kopier-zugewiesen
4 Verwendung des allgemeinen Konstruktors
5 Die Rolle des allgemeinen Konstruktors als Typumwandlungskonstruktor ist durch das Schlüsselwort explicit abgeschaltet worden
6 Auf der rechten Seite wird ein temporäres, anonymes Objekt des Typs B explizit instanziiert, das dann an b1 kopier-zugewiesen wird.

Operatorüberladung

Fast alle Operatoren wie `, `-` oder `<<` (ausgenommen `sizeof`, `.`, `?:`, `::`, `.*`) können in `C+ überladen werden. Das haben wir schon für den Datentyp std::string benutzt.

Folgende Operator-Arten gibt es in C++:

  • unäre Operatoren wie - in der Anweisung int x = -3; oder auch sizeof(int)

  • binäre Operatoren wie - oder + in der Anweisung a + b oder auch << in der Anweisung std::cout << x;

  • ternäre Operatoren wie in der Anweisung int x = (a < b ? a : b);

Operatoren werden in C++ als freie Funktionen oder als Elementfunktionen realisiert (Abschnitt 3.3.2).
Der Shift-Operator als Ausgabeoperator

Der sog. Ausgabeoperator << ist ein binärer Operator bspw. mit der Signatur

std::ostream& operator<<(std::ostream&, const Point&)

für den Typ Point.

Damit kann der Ausgabeoperator deklariert werden:

Quelltext 13. Zeilen aus der Datei point42.h [Snippet: output] 
1#include <iosfwd> (1)
2std::ostream& operator<<(std::ostream& outputStream, const Point& p);
1 Diese Include-Datei enthält die Deklaration von std::ostream

Neben der Definition gehört natürlich auch wieder ein Testfall dazu:

Quelltext 14. Zeilen aus der Datei point42.cc [Snippet: output] 
 1#include <sstream> (1)
 2std::ostream& operator<<(std::ostream& outputStream, const Point& p) {
 3    outputStream << "Point[" << p.getX() << "," << p.getY() << "," << p.getColor() << "]";
 4    return outputStream; (2)
 5}
 6SIMPLETEST("Point <<") {
 7    Point p1;
 8    std::stringstream ss; (3)
 9    ss << p1;
10    if (ss.str() != "Point[0,0,black]") return false;
11    return true;
12};
1 Diese Include-Datei ist für den Testfall notwendig
2 Dieses Durchreichen von outputStream ist für die Verkettung wichtig (s.a. reference-in reference-out)
3 Die Klasse std::stringstream ist abgeleitet von std::ostream

Dann kann der Operator verwendet werden:

 4    const Point p1;
 5    std::cout << p1 << std::endl; (1)
 6    Point p2{1.0, 2.0};
 7    p2.setColor("red");

3. Details

3.1. Freie Funktionen als Bestandteil der öffentlichen Klassenschnittstelle

Die öffentliche Klassenschnittstelle bestimmt die Menge der Operationen, die mit diesem Datentyp möglich sind. Aus diesem Grunde fallen auch i.a. die freien Operatorfunktion darunter.

Diese freien (Operator-) Funktionen sind also genauso Bestandteil der öffentlichen Schnittstelle des Datentyps wie die Elementfunktionen. Daher sollten sie auch genauso Zugriff auf die privaten Datenelemente der Klasse erhalten.

Das Thema Kapselung kann an dieser Stelle nicht ganz ausführlich betrachtet werden. Deswegen werden nur Regeln gegeben. Die Begründung für viele dieser Regeln findet sich hier.

Dies kann in C++ durch die friend-Deklaration erreicht werden:

Quelltext 16. Zeilen aus der Datei point43.h [Snippet: friend] 
1class Point {
2    friend std::ostream& operator<<(std::ostream& outputStream, const Point& p); (1)
3    friend double operator-(const Point&, const Point&); (2)
4public:
5// ...
6};
7double distance(const Point&, const Point&);
8std::ostream& operator<<(std::ostream& outputStream, const Point& p);
9double operator-(const Point&, const Point&); (3)
1 Die friend-Deklaration kann an beliebiger Stelle in der Klasse vorgenommen werden
2 Als Alternative zur Funktion distance wird der Operator - überladen
3 Deklaration des Operators -
Quelltext 17. Zeilen aus der Datei point43.cc [Snippet: friend] 
 1std::ostream& operator<<(std::ostream& outputStream, const Point& p) {
 2    outputStream << "Point[" << p.mX << "," << p.mY << "," << p.mColor << "]"; (1)
 3    return outputStream;
 4}
 5double operator-(const Point& a, const Point& b) {
 6    return std::hypot(a.mX - b.mX, a.mY - b.mY); (2)
 7}
 8SIMPLETEST("Point op-") {
 9    Point p1 = {0.0, 0.0};
10    Point p2 = {1.0, 1.0};
11    if (!Math::equal(p1 - p1, 0.0)) return false;
12    if (!Math::equal(p2 - p2, 0.0)) return false;
13    if (!Math::equal(p1 - p2, std::sqrt(2.0))) return false;
14    return true;
15};
1 Wegen der friend-Eigenschaft kann nun auf die privaten Datenelemente zugegriffen werden!
2 Auch hier ist der Zugriff auf die privaten Elemente möglich

3.2. Idiome

3.2.1. Reference-in / Reference-out

In Ergebnisrückgabe hatten wir Regeln festgelegt, wann eine Funktion ein Ergebnis als Referenz zurückliefern darf. Diese Regel können wir am Beispiel des Ausgabeoperators erweitern.

Quelltext 19. Zeilen aus der Datei point44.cc [Snippet: out] 
1std::ostream& operator<<(std::ostream& outputStream, const Point& p) {
2    outputStream << "Point[" << p.mX << "," << p.mY << "," << p.mColor << "]";
3    return outputStream; (1)
4}
1 Nach der Regel reference-in / reference-out darf outputStream als Referenz zurückgegeben werden.
Regel reference-in / reference-out

Ein Referenzparameter (zusätzlicher Name für ein Objekt, dass beim Aufrufer existiert) kann auch wieder als Referenz an den Aufrufer zurückgegeben werden.

Dadurch ist auch eine Verkettung des Operators möglich (s.a. Verkettung von Mutatoren).

4. Rückblick

4.1. Domänenspezifische Datentypen

Die primitiven Datentypen wie etwa double tragen keine Semantik: den beiden double-Parameteren in dem Konstruktor Point::Point(double, double) ist nicht zu entnehmen, bei welchem es sich um die x oder y-Koordinate handelt. Das birgt Verwechselungsgefahr.

Was bedeutet folgendes:

Point p = {1.0, 3.14};

Da in C++ die UDT so wie primitive DT verwendet werden können, ist es möglich, sich geeignete Datentypen für die Anwendungsdomäne zu schaffen. Diese besitzen dann eine für die Domäne spezifische Semantik.

POD Datentypen
Als POD (plain old datatype) Datentypen werden allgemein Datentypen bezeichnet, die Daten zwar kapseln, aber keine interne Zustandslogik aufweisen. Dies stellt sich allgemein so dar, dass diese Typen keine Elementfunktionen (auch Konstruktoren) enthalten und die Datenelemente public sind.

Dies führt zu den beiden Klassen XCoor und YCoor für kartesische Koordinaten:

Quelltext 22. Zeilen aus der Datei point44.h [Snippet: cartesian] (einige Zeilen nicht dargestellt)
1class XCoor { (1)
2public:
3    double mValue {0.0};
4};
5class YCoor { (2)
6public:
7    double mValue {0.0};
8};
1 Diese Klasse ist ein POD (plain old datatype) zur typsicheren Verwendung von double-Werten als x-Koordinatenwerte
2 Diese Klasse ist ein POD (plain old datatype) zur typsicheren Verwendung von double-Werten als y-Koordinatenwerte

Der Konstruktor von Point ist nun natürlich darauf anzupassen:

Quelltext 23. Zeilen aus der Datei point44.cc [Snippet: cartesian] 
1Point::Point(const XCoor x, const YCoor y) : mX{x.mValue}, mY{y.mValue} {
2}

4.1.1. SVG-Datei mit viewBox

Die bisherige Realisierung der Klasse SVGFile hatte eine parametrisierbare, aber feste Ausdehnung der Zeichenfläche. Diese musste bekannt sein.

Besser ist es, die notwendige Größe der Zeichenfläche und deren Ursprung durch die enthaltenen Elemente bestimmen zu lassen, damit keine Anteile abgeschnitten werden. Dazu kann das viewBox SVG-Attribute verwendet werden.
