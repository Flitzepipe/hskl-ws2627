7. Erste Schritte

Wir benutzen zunächst das folgende C++-Programm, um zu erkunden, welche Version unser verwendeter Compiler unterstützt:

Quelltext 1. Zeilen aus der Datei ppc00a0.cc 
1#include <iostream>
2int main() {
3    std::cout << "Compiler-Version:\t" << __cplusplus << std::endl;
4}

Als Augabe sollten wir etwa folgendes erhalten (dazu muss das Programm natürlich vorher kompiliert worden sein):

Ausgabe 1. Ausgabe des Programms: ppc00a0
Compiler-Version:	201703
Es sollte etwas erscheinen, was größer als 201103 ist! Die Angabe setzt sich zusammen aus dem Jahr (2011) und dem Monat (03) der Veröffentlichung der Version des C++-Standards.
__cplusplus ist ein Präprozessorsymbol, dass vom Präprozessor automatisch den passenden Wert erhält.

8. Kompilation eines C++-Programms

Wir verwenden VSCode als IDE (später erweitert um GitHub Copilot). Die Programme können aber auch direkt auf der Kommandozeile übersetzt werden (hier am Beispiel gcc(1)):

Quelltext 2. Kommando 1: Kompilation der Übersetzungseinheit ppc00a0.cc
$ g++ -o ppc00a0 ppc00a0.cc

  • Es wird die Übersetzungseinheit ppc00a0.cc kompiliert (und nur diese!).

  • Es entsteht eine ausführbare Programmdatei ppc00a0

    • Lässt man die Option -o weg, entsteht eine Programmdatei a.out (bzw. bei MS-Windows: a.exe )

Um das Programm auszuführen, schreibt man:

Quelltext 3. Kommando 2: Ausführen der ausführbaren Programmdatei ppc00a0
$ ./ppc00a0

Wir übersetzen alle unsere Programme auf der höchsten Warnstufe:

Quelltext 4. Kommando 3: Kompilation der Übersetzungseinheit ppc00a0.cc auf der höchsten Warnstufe des Compilers
$ g++ -Wall -Wextra -o ppc00a0 ppc00a0.cc
Die Optionen -Wall und -Wextra schalten bei dem GNU-Compiler (und auch beim CLang) die höchste Warnstufe ein. Auch hierbei sollten keine Warnungen erscheinen!

2public:       (2)

4        std::cout << "Hallo Welt\n"; (4)
5    }
6}; (5)

10. Die freie Funktion main()

Jedes C++-Programm braucht eine freie Funktion main

  • int main() {…​} oder

  • int main(int argc, char** argv) {…​}

Wir fügen eine solche freie Funktion hinzu:

Quelltext 7. Zeilen aus der Datei ppc00b0.cc [Snippet: main] 
1int main() { (1)
2    Hello::main(); (2)
3}
1 Jedes Programm beginnt in der freien Funktion int main()
2 Aufruf der Klassenmethode (statische Elementfunktion) void main() aus der Klasse Hello

11. Das gesamte Programm

Fügen wir alles zusammen, so erhalten wir:

Quelltext 8. Zeilen aus der Datei ppc00b0.cc 
 1#include <iostream> (1)
 2class Hello { (2)
 3public:       (3)
 4    static void main() { (4)
 5        std::cout << "Hallo Welt\n"; (5)
 6    }
 7}; (6)
 8#ifndef NO_MAIN (7)
 9int main() { (8)
10    Hello::main(); (9)
11}
12#endif (10)
1 Präprozessor include-Anweisung, damit die Ausgabe möglich ist
2 Beginn der Klassendefinition
3 Beginn der public-Sektion
4 Definition der Klassenmethode void main() (statische Elementfunktion)
5 Ausgabe mit Hilfe des sog. Ausgabe-Operators <<
6 das Semikolon ist hier ganz wichtig!!!
7 Präprozessoranweisung (nur zu Demonstrationszwecken)
8 Jedes Programm beginnt in der freien Funktion int main()
9 Aufruf der Klassenmethode (statische Elementfunktion) void main() aus der Klasse Hello
10 gehört zu #ifndef von oben

Und hier nochmal ohne die störenden Annotationen:

Quelltext 9. Zeilen aus der Datei ppc00b0.cc 
 1#include <iostream>
 2class Hello {
 3public:
 4    static void main() {
 5        std::cout << "Hallo Welt\n";
 6    }
 7};
 8#ifndef NO_MAIN
 9int main() {
10    Hello::main();
11}
12#endif

12. Vergleich mit Java

Zum Vergleich dasselbe in Java:

Quelltext 10. Zeilen aus der Datei Hello.java 
1class Hello { (1)
2    public static void main(String[] arguments) { (2)
3        System.out.print("Hallo Java-Welt\n"); (3)
4    }
5}

2 Klassenmethode
3 Ausgabe auf Konsole

13. Unterschiede zu Java

Was fällt bisher auf?

  • Am Ende der Klassendefinition steht ein Semikolon!

  • Sichtbarkeiten der Elemente (Elementfunktionen, Datenelemente (Attribute)) in einer Klasse werden durch Sektionen festgelegt.

  • Das Programm beginnt in einer freien Funktion int main() statt in einer (Java)-Klassenmethode static void main(String[]).

    • Die freie Funktion darf zwei Signaturen haben:

      1. int main()

      2. int main(int argc, char** argv)

    • Die zweite Signatur können wir momentan noch nicht entschlüsseln ;-)

  • Die Ausgabe auf die Konsole wird mit dem sog. Ausgabe-Operator << erledigt:

    • std::cout << "text"

    • Bislang kannten wir << von Java als bit-shift-Operator

  • Inklusionsanweisung des Präprozessors

  • Kein package-Konstrukt

14. Der Kompilationsvorgang

Implementierungsdatei
Eine Implementierungsdatei enthält Definitionen von (freien / Element-) Funktionen, Variablen, etc. Sie haben üblicherweise die Namensendung .cc oder .cpp, also bspw. den Namen abc.cc.
Header-Datei
Eine Header-Datei (Include-Datei) wird vom Präprozessor in eine Implementierungsdatei eingefügt. Selbstdefinierte Header-Dateien haben üblicherweise die Namensendung .h, bspw. also den Namen abc.h.
Übersetzungseinheit
Eine Übersetzungseinheit ist die Menge Code, die der C++-Compiler als eine unabhängige Einheit compiliert. Der Präprozessor bildet eine Übersetzungseinheit aus der Implementierungsdatei (genau eine) und den hiervon inkludierten Headerdateien (beliebig viele).
Präprozessor
Der Präprozessor ist ein nicht-interaktiver Editor. Wichtige Präprozessor-Anweisungen sind die #include-Anweisung, die Symboldefinitionsanweisung #define und die Auswahlanweisung #ifdef bzw. #if.
Compiler
Der Compiler übersetzt den Code jeder Übersetzungseinheit getrennt in plattformspezifischen Maschinencode.
Objektdatei
Der plattformspezifische Maschinencode wird in einer Objektdatei vom Compiler abgelegt.
Binder (Linker)
Der Binder fügt die Objektdateien (zusammen mit Maschinencode aus den Bibliotheken) zu einer ausführbaren Programmdatei zusammen.
Bibliothek (Library)
Eine Bibliothek ist ein Archiv von plattformspezifischem Maschinencode. Beispiele sind die C-Bibliothek oder die Standard-C++-Bibliothek.
Programmdatei
Eine Datei mit plattformspezifischem Maschinencode und genau einer freien Funktion int main(). Diese Datei darf ausgeführt / gestartet werden (je nach Betriebssystem über einen Kommandozeilen-Interpreter (Shell) oder den Dateisystem-Browser.)

16. Ein erweitertes Beispiel in C++

Nun dasselbe in C++:

Quelltext 13. Zeilen aus der Datei ppc00b1.cc 
 1#include <iostream>
 2#include <vector>
 3#include <string>
 4#include <iterator>
 5class Hello {
 6public:
 7    static void main(const std::vector<std::string> arguments) {

10            std::cout << s << std::endl;
11        }

Die Codezeilen

1std::vector<std::string> args{argv, argv + argc};

können wir noch nicht verstehen.

Lediglich die Zeile

Quelltext 15. Zeilen aus der Datei ppc00b1.cc [Snippet: call] 
1Hello::main(args); (1)

kennen wir schon.

17. Klasse Hello

Schauen wir uns die Klasse Hello genauer an:

Quelltext 16. Zeilen aus der Datei ppc00b1.cc [Snippet: Hello] 
1class Hello {
2public:
3    static void main(const std::vector<std::string> arguments) { (1)
4        std::cout << "Hallo C++-Welt" << std::endl; (2)
5        for(std::string s: arguments) { (3)
6            std::cout << s << std::endl; (4)
7        }
8    }
9};
1 arguments ist Parametervariable der Funktion
2 Ausgabe eines C-Strings
3 Container-for-loop (range-based-for) über den Container arguments
4 Ausgabe von s mit Zeilenvorschub

Der Aufruf des Programms (Programmdatei ppc00b1)

Quelltext 17. Kommando 6: Starten der ausführbaren Programmdatei ppc00b1 mit den Parametern abc und def
$ ./ppc00b1 abc def

liefert dann

Ausgabe 4. Ausgabe des Programms: ppc00b1

In C++ spricht man oft von Elementfunktionen und Datenelementen (Objektvariable, Klassenvariable) statt von Methoden und Attributen. Daneben existieren auch noch freie Funktionen.

18. Präprozessor

Die folgenden Präprozessoranweisungen sind zu beachten:

Quelltext 18. Zeilen aus der Datei ppc00b1.cc [Snippet: include] 
1#include <iostream> (1)
2#include <vector>   (2)
3#include <string>   (3)
4#include <iterator>
1 Notwendig, damit man std::cout << "ausgabe" schreiben kann
2 Notwendig, damit man den generischen Typ std::vector<T> verwenden kann
3 Notwendig, damit man den Typ std::string verwenden kann.

19. Elementfunktionsdefinition

Eine Funktionsdefinition besteht (bis jetzt) aus

[static] <Typ> <Name>(<Parameterliste>) {<Anweisungen>}

Die Sichtbarkeit ergibt sich aus der Sektion (public, protected, private) der Klasse. Die Parameterliste besteht wie bei Java aus <Typ> <Parametername>, …​.

20. Datentyp std::string und "ein C-String"

Zur Aufnahme von Zeichenketten verwenden wir den Datentyp std::string ähnlich wie in Java den Datentyp String. Die Angabe "ein C-String" heißt String-Literal, der Datentyp hiervon ist const char* (noch unbekannt) oder auch C-String genannt. Ein C-String ist jedoch implizit in den Datentyp std::string konvertierbar.
Der Datentyp std::string zählt nicht zu den sog. primitiven Datentypen (eingebauten Datentypen) von C++. Man benötigt für die Deklaration (Bekanntmachung) die Präprozessor-Anweisung #include <string> (std::string). Die Definition aller Elementfunktionen dieses Typs befindet sich in der C++-Standardbibliothek.

21. Namensräume

Um Kollisionen von Namen zu vermeiden, existieren sog. Namensräume. Damit kann man bspw. unterschiedliche Klassen Person trennen. Der Namensraum steht vor dem Datentyp, getrennt durch den Bereichsoperator (scope-operator) :: wie bei std::string: der Namensraum std ist reserviert für die C++-Standardbibliothek!
Benutzen Sie zunächst nicht die using-Anweisung using namespace std;, die man in vielen Anleitungen findet!

22. Datentyp std::vector<Elementtyp>

Statt eines (rohen) Arrays wie in Java verwenden wir (zunächst) den Container std::vector. Dies ist ein generischer Datentyp (Template, ähnlich den generics in Java), bei dem wir angeben müssen, welchen Datentyp die einzelnen Elemente haben.
Arrays are stupid, too stupid to know their size.
— Bjarne Stroustrup
Der Datentyp std::vector muß durch Inklusion der Header-Datei <vector> bekannt gemacht werden.

23. Deklarationen und Definitionen

Die Bezeichner in einem Programm müssen bekannt gemacht werden.

Deklaration (s.a. Details in LE 01)
Eine Deklaration legt den Namen und den Typ eines Konstruktes / Elementes fest.
Definition (s.a. Details in LE 01)
Eine Definition ist eine Deklaration, die zusätzlich das Konstrukt / Element vollständig spezifiziert (etwa den Speicher für eine Variable, den Funktionsrumpf einer (Element-) Funktion. Damit ist jede Definition auch gleichzeitig eine Deklaration.
One Definition Rule
In einem Programm darf jedes Konstrukt nur einmal definiert werden.

24. Code-Strukturierung

Durch die Unterscheidung von Deklaration und Definition können wir den Code beliebig strukturieren.

Um ein Element zu verwenden, muss der Compiler mindestens vorher die Deklaration gesehen haben!

Quelltext 19. Zeilen aus der Datei ppc00c1.cc 
 1#include <iostream>
 2#include <vector>
 3#include <string>
 4#include <iterator>
 5class Hello { (1)
 6public:
 7    static void main(std::vector<std::string> arguments); (2)
 8};
 9int main(const int argc, const char* const* const argv) {
10    std::vector<std::string> args{argv, argv + argc};
11    Hello::main(args); (3)
12}
13void Hello::main(const std::vector<std::string> arguments) { (4)
14    std::cout << "Hallo C++-Welt" << std::endl;
15    for(std::string s: arguments) {
16        std::cout << s << std::endl;
17    }
18}
1 Deklaration der Klasse Hello
2 Deklaration der statischen Element-Funktion void main()
3 Die obige Deklaration hat das Element Hello::main() bekanntgemacht, deswegen können wir die Funktion aufrufen
4 Definition der (statischen) Element-Funktion void main()
Spielen Sie selbst Compiler und lesen Sie den Code von oben nach unten: beantworten Sie dabei bei jedem Symbol (Bezeichner) die Frage nach dem Datentyp des Symbols.

25. Code-Strukturierung und Dateien

Die obige Aufteilung des Codes funktioniert auch über Dateigrenzen hinweg!
Quelltext 20. Zeilen aus der Datei ppc00c2.cc 
1#include <iostream>
2#include <vector>
3#include <string>
4#include <iterator>
5#include "hello.h" (1)
6int main(const int argc, const char* const* const argv) {
7    std::vector<std::string> args{argv, argv + argc};
8    Hello::main(args); (2)
9}
1 Die Datei wird in demselben Verzeichnis gesucht
2 Das obige #include-Statement hat die Klasse Hello und die Elementfunktion Hello::main() bekannt gemacht
Quelltext 21. Zeilen aus der Datei hello.h

 2#define HELLO_H (2)
 3#include <iostream>
 4#include <vector>
 5#include <string>

 7public:
 8    static void main(std::vector<std::string> arguments); (4)
 9};
10#endif (5)
1 include-guard: Teil 1
2 include-guard: Teil 2
3 Deklaration der Klasse Hello
4 Deklaration der Element-Funktion main()
5 include-guard: Teil 3

1#include "hello.h" (1)
2void Hello::main(std::vector<std::string> arguments) { (2)

2 Definition der Element-Funktion main()

26. Übersetzungseinheiten und Kompilation

Bei der Kompilation muss allerdings beachtet werden, dass das Programm nun aus mehreren Übersetzungseinheiten besteht.

Alle Übersetzungseinheiten müssen dem Compiler-Frontend angegeben werden.

Das Compiler-Frontend ruft dann Präprozessor sowie Compiler für jede Übersetzungseinheit auf und benutzt anschließend den Linker, um ein ausführbares Programm zu erstellen (und notwendige Bibliotheken dazu zu binden).
Quelltext 23. Kommando7.
$ g++ -Wall -Wextra -o ppc00c2 ppc00c2.cc hello.cc

27. Namenskonventionen

In unserem Beispiel benennen wir also nun

hello.h

die Header-Datei für die Klasse Hello (Schnittstellendefinition)
hello.cc

die Implementierungs-Datei für die Klasse Hello
ppc00c2.cc

den restlichen Code, hier die Funktion main()

Es gibt keine vorgeschriebenen Namen für Header- oder Implemetierungsdateien, aber Konventionen:

Header-Datei

für eine Klasse Abc → abc.h, sonstiges Modul def → def.h
Implementierungsdatei

für eine Klasse Abc → abc.cc, sonstige Modul def → def.cc
