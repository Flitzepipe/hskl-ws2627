2. Eine Klasse Point

2.1. Modellierung eines geometrischen Punktes

Die Klasse Point soll einen geometrischen Punkt in der zweidimensionalen Ebene modellieren.

Dazu benötigen wir zwei Datenelemente (Attribute, Objektvariablen) (hier: mX und mY) für die Koordinaten des Punktes.

Bild 1. Die einfache Klasse Point (zunächst werden die Koordinaten als int-Datenelemente dargestellt)

2.2. Umsetzung der Klasse Point in C++

Die Deklaration des Klasse Point in der Header-Datei point00.h:

Quelltext 1. Zeilen aus der Datei point00.h 
1#ifndef POINT_H (1)
2#define POINT_H
3class Point { (2)
4public: (3)
5    int mX; (4)
6    int mY; (5)
7};
8#endif (6)
1 Beginn des include-guards
2 Deklaration des Typs Point
3 Die voreingestellte Sichtbarkeit private wird geändert zu public
4 Deklaration des öffentlichen Datenelementes mX mit Datentyp int
5 Deklaration des öffentlichen Datenelementes mY mit Datentyp int
6 Ende des include-guards

Weil wir noch keine Elementfunktionen, Klassenvariablen, freie Funktionen, etc. benötigen, bleibt die Implementierungs-Datei point00.cc fast leer:

Quelltext 2. Zeilen aus der Datei point00.cc 
1#include "point00.h"

Um die Klasse 'Point' zu verwenden, schreiben wir in einer weiteren Implementierungs-Datei ppc0100.cc die freie Funktion main():

Quelltext 3. Zeilen aus der Datei ppc0100.cc 
 1#include <iostream>
 2#include "point00.h" (1)
 3int main() {
 4    Point p1; (2)
 5    std::cout << "x="
 6              << p1.mX (3)
 7              << "\ty="
 8              << p1.mY (4)
 9              << std::endl;
10}
1 Bindet die Deklaration des Typs Point ein
2 Definition eine Variable des Typs Point mit dem Namen p1
3 Das Datenelement mX ist öffentlich
4 Der Operator . ermöglicht den Elementzugriff

Zum Kompilieren geben wir alle Implementierungsdateien - also point00.cc und ppc0100.cc - unseres Programmes an:

Quelltext 4. Kommando1: Aufruf des Kompilers g++ und Angabe alle Implementierungsdateien
$ g++ -Wall -Wextra -Weffc++ -o ppc0100 ppc0100.cc point00.cc

Dann starten wir unser Programm ppc0100

Quelltext 5. Kommando2: Start des Programms in der ausführbaren Programmdatei ppc0100
$ ./ppc0100

und erhalten:

Ausgabe 1. Ausgabe des Programms: ppc0100
x=0	y=0
Man achte in der obigen Ausgabe auf die Werte der Punktkoordinaten: je nach Ausführungsumgebung und -zeitpunkt können hier unterschiedliche (zufällige) Ausgaben erscheinen (s.a. Initialisierung).

2.3. Details zur ersten Version

Selbstdefinierte Datentypen
In C++ werden selbstdefinierte DT wie Point (UDT: user defined type) genauso wie die eingebauten DT wie etwa int behandelt. Im Gegensatz zu Java ist kein new-Operator notwendig.
Sichtbarkeiten der Elemente

Die Sichtbarbeit von Elementen einer Klasse wird durch Sektionen der Klasse festgelegt. Voreingestellt ist private, Dies kann durch die Zugriffsspezifizierer public:, protected: und private: geändert werden.

private

Zugriff nur durch Funktionen desselben Datentyps
protected

Zugriff auch durch Funktionen von abgeleiteten Datentypen
public

Zugriff durch beliebige Funktionen
Quelltext 6. Zeilen aus der Datei point01.h 
 1#ifndef POINT01_H (1)
 2#define POINT01_H
 3class Point {
 4    (2)
 5    int mAbc; (3)
 6protected:    (4)
 7    int mDef; (5)
 8public:       (6)
 9    int mGhi; (7)
10private:      (8)
11    int mJkl; (9)
12};
13#endif // POINT01_H
1 include-guard
2 hier beginnt die private Sektion der Klasse
3 Zugriff ist private
4 hier beginnt die protected Sektion der Klasse
5 Zugriff ist protected
6 hier beginnt die public Sektion der Klasse
7 Zugriff ist public
8 hier beginnt wieder die private Sektion der Klasse
9 Zugriff ist private
Zugriff auf Datenelemente
Der Zugriff auf Elemente eines Objektes erfolgt mit dem Elementzugriffsoperator .: <objektname>.<datenelement> bzw. <objektname>.<elementfunktion(<parameterliste>)
Initialisierung der Datenelemente
Ohne besondere Maßnahmen verwendet C++ die Standard-Initialisierung von Variablen (z.B. lokale oder Objekt-Variablen). Bei automatischen Variablen eines primitiven DT bedeutet das, nichts zu tun, d.h. der Inhalt der Variablen erscheint zufällig.

3.1. Veränderte Modellierung

Bild 2. Die verbesserte Klasse Point

3.2. Veränderte Umsetzung in C++

Wir führen die Beobachter-Funktionen als Bestandteil der öffentlichen Schnittstelle ein:

Quelltext 7. Zeilen aus der Datei point02.h 
 1#ifndef POINT02_H
 2#define POINT02_H
 3class Point {
 4public:
 5    double getX() const; (1)
 6    double getY() const;
 7private:
 8    double mX = 0.0; (2)
 9    double mY = 0.0;
10};
11#endif // POINT02_H
1 Beobachter-Elementfunktionen werden mit dem Schlüsselwort const qualifiziert, da sie das Objekt nicht verändern.
2 Dieses Datenelement wird mit Hilfe eines in-class-initializer mit dem Wert 0.0 initialisiert.
Beobachter-Elementfunktionen (Observer)
Diese Elementfunktionen liefern als Ergebnis einen (Teil)-Zustand des Objektes zurück: sie verändern den sichtbaren Zustand des Objektes allerdings nicht. Damit dies der Compiler überprüfen kann, bekommen diese Elementfunktionen den Zusatz const!

Die Definition der Elementfunktionen kommt in die Implementierungsdatei point02.cc:

Quelltext 8. Zeilen aus der Datei point02.cc 
1#include "point02.h"
2double Point::getX() const {
3    return mX;
4}
5double Point::getY() const {
6    return mY;
7}

Natürlich muss nun auch diese veränderte Schnittstelle aus point02.h inkludiert werden:

Quelltext 9. Zeilen aus der Datei ppc0102.cc 
 1#include <iostream>
 2#include "point02.h" (1)
 3int main() {
 4    Point p1;
 5    std::cout << "x="
 6              << p1.getX() (2)
 7              << "\ty="
 8              << p1.getY() (3)
 9              << std::endl;
10}
1 Bindet die verbesserte Deklaration des Typs Point ein
2 Die Elementfunktion getX() ist öffentlich
3 Die Elementfunktion getY() ist öffentlich

Dann bekommen wir das gewünschte Ergebnis:

Ausgabe 2. Ausgabe des Programms: ppc0102
x=0	y=0

4. Die nächste Stufe

4.1. Punkte mit beliebigen Koordinaten

Konstruktoren
Der initiale Zustand eines Objektes wird durch einen Konstruktor hergestellt. Konstruktoren können wie andere Elementfunktionen überladen werden.

In unserem Beispiel bedeutet das, dass wir einen Konstruktor brauchen, mit dem wir die Koordinaten, d.h. den Zustand initial setzen können.

Bild 3. Die nochmals verbesserte Klasse Point mit einem allgemeinen Konstruktor.

4.2. Die Umsetzung in C++

Zunächst fügen wir die Deklaration des Konstruktors der Schnittstelle der Klasse Point in point03.h hinzu:

Quelltext 10. Zeilen aus der Datei point03.h 
 1#ifndef POINT03_H
 2#define POINT03_H
 3class Point {
 4public:
 5    Point(double x, double y); (1)
 6    double getX() const;
 7    double getY() const;
 8private:
 9    double mX = 0.0;
10    double mY = 0.0;
11};
12#endif // POINT03_H
1 Allgemeiner Konstruktor

Natürlich müssen wir diese Elementfunktion Konstruktor auch in point03.cc definieren:

Quelltext 11. Zeilen aus der Datei point03.cc [Snippet: ctor] 
1Point::Point(const double x, const double y) :
2    mX{x}, mY{y} (1)
3{
4}
1 Initialisierungsliste mit den Elementinitialisieren für mX und mY
Initialisierungsliste, Elementinitialisierer und in-class-Initialisierer

Alle Datenelemente primitiver Datentypen sollten explizit initialisiert werden. Obwohl die non-static Datenelemente in der Klassendeklaration nicht definiert werden (ein Objekt wird ja erst durch eine Definition erzeugt), können sie dort schon durch in-class-Initialisierer zur Initialisierung vorgemerkt werden.

  1. in-class-Initialisierer in double mX{0.0}; (brace) oder double mX = 0.0 (equal) Form

  2. Elementinitialisierer der Initialisierungsliste: Point(double x, double y): mX(x), mY(y) {} in der Reihenfolge der Deklaration

Zuweisungen im Konstruktorrumpf sollten nicht verwendet werden!

Dann können wir den Konstruktor bei der Definition von Variablen, also in dem Moment, in dem auch der Speicher für das Objekt bereitgestellt wird, verwenden:

Quelltext 12. Zeilen aus der Datei ppc0103.cc [Snippet: main] 
1#include <iostream>
2#include "point03.h" (1)
3int main() {
4    double x{1.0};  (2)
5    double y{2.0};  (3)
6    Point p1{x, y}; (4)
7    std::cout << "x=" << p1.getX() << "\ty=" << p1.getY() << std::endl;
8// ...
9}
1 Bindet die nochmals verbesserte Deklaration des Typs Point ein
2 Definition und Initialisierung der Variable x vom Typ double
3 Definition und Initialisierung der Variable y vom Typ double
4 Definition und Initialisierung der Variable p1 vom Typ Point mit dem allgemeinen Konstruktor
Gleichförmigkeit von primitiven und selbstdefinierten Datentypen
C++ behandelt die eingebauten (primitiven) und selbstdefinierten Datentypen - bis auf wenige Ausnahmen⁠[1] - gleich. Somit kann in beiden Fällen dieselbe Syntax verwendet werden.

Damit bekommen wir dann auch folgende Ausgabe:

Wenn wir allerdings zusätzlich folgendes versuchen:

 8#ifdef WITH_ERROR   (5)

10#endif
11}

2 Definition und Initialisierung der Variable x vom Typ double
3 Definition und Initialisierung der Variable y vom Typ double

5 Um die Fehlermeldung zu sehen, muss mit dem Schalter -DWITH_ERROR kompiliert werden

Der Standardkonstruktor

Der Standardkonstruktor einer Klasse Abc ist Abc::Abc(), also der Konstruktor, den ich ohne Parameter aufrufen kann:

Abc a1;   // Standardkonstruktor
Abc a2(); // Achtung Falle: Deklaration einer Funktion a2() mit Rückgabetyp Abc

Wenn sonst kein allgemeiner Konstruktor deklariert wird, so wird der Standardkonstruktor vom Compiler erzeugt. Dieser führt eine Default-Initialisierung aller Datenelemente der Klasse durch.

Achtung: Objektvariablen primitiver Datentypen → kein definierter Wert!

4.3. Noch mehr Konstruktoren

Um das Problem des fehlenden Standardkonstruktors zu lösen, fügen wir wieder einen eigenen Standardkonstruktor Point::Point() hinzu: die Deklaration in point04.h und die Definition in point04.cc:

Quelltext 15. Zeilen aus der Datei point04.h [Snippet: Point] 
1class Point {
2public:
3    Point(); (1)
4    Point(double x, double y); (2)
5// ...
6private:
7// ...
8};
1 Deklaration eines eigenen Standardkonstruktors
2 Deklaration eines allgemeinen Konstruktors
Quelltext 16. Zeilen aus der Datei point04.cc [Snippet: ctor] 
1Point::Point() { (1)
2    (2)
3}
4Point::Point(const double x, const double y) :
5    mX{x}, mY{y} (3)
6{
7}
1 Ohne Initialisierungsliste werden die Datenelement durch die in-class-Initialisierer initialisiert
2 leerer Standardkonstruktor: äquivalent dem vom Compiler generierten Standardkonstruktor
3 allgemeiner Konstruktor initialisiert die Daten-Elemente
Das Überladen von Elementfunktionen (und freien Funktionen)
Deklariert man Funktionen mit demselben Namen, aber unterschiedlichen Parameterlisten, so spricht man vom Überladen der Funktionen. Dies führt zu unterscheidlichen Signaturen (Name und Parameterliste). Der Rückgabetyp gehört nicht zur Signatur. Korrektes Überladen setzt unterscheidliche Signaturen voraus.

Damit ist es dann möglich, folgendes zu schreiben (s.a. Abschnitt 5.2):

Quelltext 17. Zeilen aus der Datei ppc0104.cc [Snippet: init] 
1Point p1;
2Point p2{1.1, 1.1};    (1)
1 Initialisierung durch direct-initialization

5. Details

5.1. Datentypen, Objekte, Werte, etc.

Das Konzept der Datentypen ist sehr wichtig für das weitere Verständnis, deswegen folgt die Definition der damit in Verbindung stehenden Begriffe:

Datentyp

Der Datentyp definiert eine Menge von möglichen Werten sowie eine Menge von Operationen.
Objekt

Ein Objekt ist ein Speicherbereich, in dem ein Wert des gegebenen Datentyps abgelegt ist.
Wert

Ein Wert ist eine Folge von Bits mit einem Datentyp.
Variable

Eine Variable ist ein Objekt mit einem Namen (Bezeichner).
Deklaration

Eine Deklaration ist eine Anweisung, die einem Objekt einen Namen zuordnet.
Definition

Eine Definition ist eine Deklaration, die auch noch zusätzlich Speicher für das Objekt reserviert.

5.3. Vom Compiler generierte Elementfunktionen

Wir mussten den Standardkonstruktor nur deshalb schreiben, weil die Deklaration des allgemeinen Konstruktors Point::Point(double, double) die automatische Generierung verhinderte. Man kann dies aber wieder aktivieren (= default).

Wenn man Dateien umbenennt, kann es bei dem normalen include-guard zu Problemen führen. Die compiler-spezifische Anweisung #pragma once erfüllt denselben Zweck ohne diese Fehlerchance. Sie ist jedoch nicht standardisiert, aber alle gängigen Compiler unterstützen das.
Quelltext 19. Zeilen aus der Datei point05.h [Snippet: Point] 
1#pragma once (1)
2class Point {
3public:
4    Point() = default; (2)
5    Point(double x, double y); (3)
6// ...
7private:
8// ...
9};
1 der bessere include-guard
2 Generierung durch den Compiler erzwingen
3 Deklaration eines allgemeinen Konstruktors
