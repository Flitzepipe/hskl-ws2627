2. Arten der Polymorphie

Üblicherweise wird die Polymorphie in der objektorientierten Programmierung in die folgenden Arten unterteilt:

  • ad-hoc-Polymorphie

  • Inklusionspolymorphie

  • parametrische Polymorphie

Sowohl die ad-hoc-Polymorphie und die Inklusions-Polymorphie sind gute Bekannte.

2.1. Ad-hoc-Polymorphie

In den meisten (objektorientierten) Programmiersprachen sind die Operatoren für die primitiven (eingebauten) Datentypen überladen. So etwa der +-Operator für die Datentypen int oder double, manchmal auch für den Datentyp einer Zeichenkette:

int x = 1 + 2; (1)
double y = 1.3 + 2.4; (2)
1 Der Algorithmus des Operators + ist auf den ganzzahligen Datentyp int abgestimmt.
2 Dieser Algorithmus der Operators arbeitet anders.

In C++ gehört die ad-hoc-Polymorphie elementar zur Sprache dazu in Form von Funktionsüberladung, und zwar als

  • Überladene Operatoren für primitive Datentypen

  • Überladen von freien Funktionen

    • damit auch überladene Operatoren für UDT

  • Überladen von Elementfunktionen

    • damit auch überladene Operatoren für UDT

2.2. Inklusionspolymorphie

In den objektorientierten Programmiersprachen wird die Inklusionspolymorphie durch das sog. Vererbungsprinzip und dynamisches Binden erreicht. Ein Subtyp kann immer an die Stelle eines Basistyps treten, da er alle Eigenschaften der öffentlichen Schnittstelle des Basistyps erfüllt.

In C++ erhalten wir die Inklusionspolymorphie durch die öffentliche (public) Vererbung:

1

3

class Base {};
class Derived : public Base {}; 
void foo(const Base&) {}
int main() {
    Derived d;
    foo(d); 
}
1 Vererbung
2 Das in foo(const Base&) referenzierte Objekt hat den Typ Derived.

In C++ wird bei nicht-virtuellen Elementfunktionen statisches Binden angewendet. Um dynamisches Binden (Laufzeit-Polymorphie) zu erhalten, müssen die Elementfunktionen als virtual gekennzeichnet werden.

2.3. Parametrische Polymorphie

Die parametrische Form der Polymorphie erlaubt es nun zusätzlich, Datentypen und ihre Operationen bzw. allgemein Algorithmen unabhängig von zu ihrer Definition benötigten anderen Datentypen zu formulieren. Das bedeutet, dass Operationen bzw. Algorithmen generisch formuliert werden und führt damit zur generischen Programmierung.

Ohne die Möglichkeit einer parametrischen Polymorphie kann man zwar durch Funktions-überladung (ad-hoc-Polymorphie) polymorphe Operationen erreichen, dies führt dann aber oft zu strukturell identischem Code:

Diese Form der Polymorphie erreicht man in C++ durch sog. Templates, also Schablonen. Mit ihrer Hilfe kann der Compiler bei Erfüllung aller Vorraussetzungen den konkreten Code für einen bestimmten Datentyp generieren.

Templates sind also eine Form von Code-Generatoren.

3. Templates in C++

Das obige Beispiel einer generischen Funktion T maximum(T, T) ist in C++ direkt durch Abschnitt 3.1 zu erreichen. Aber auch Klassen lassen sich durch Klassentemplates parametrieren.

3.1. Funktionstemplates

Ein Funktionstemplate ist die Schablone, aus der der Compiler auf Anforderung eine konkrete Funktion, die Templatefunktion generiert.

3.1.1. Ein einfaches Beispiel

Das obige Beispiel kann man direkt in C++ umsetzen:

T maximum(T a, T b) { 
    if (a > b) { 
        return a;
    }
    return b;

1 Template-Präambel mit T als Template-Typ-Parameter
2 Hier steht T für einen beliebigen Datentyp (T muss kopierbar sein)
3 Der Typ T muss allerdings die >-Operation ermöglichen.

Als vereinfachten Mechanismus, wie aus einem Funktionstemplate eine Templatefunktion wird, kann man sich vorstellen, dass der Compiler zunächst den sog. Template-Typ-Parameter T durch einen konkreten Datentyp (bspw. int) ersetzt. Dies führt dann zu einem zu dieser Variante identischen Code, der aber durch den Compiler generiert wird. Dieser generierte Code wird anschließend vom Compiler selbst dann auch noch übersetzt.

Weil das Funktionstemplate auch mit UDT eingesetzt werden soll, folgenden wir unseren Regeln zur Rückgabe und Parameterübergabe:

3.1.2. Definition

Wie der Name schon sagt, ergibt eine Template-Definition nur eine Schablone, aus der dann auf Anforderung konkreter Code generiert wird.

Eine Template-Definition (eingeleitet durch die Template-Präambel) ist noch kein konkreter Code! Daher definiert ein Funktionstemplate noch keine Funktion wie eine Funktionsdefinition. Auch ein Klassentemplate definiert noch keinen Datentyp wie eine Klassendeklaration / -definition.

Vielmehr definiert ein Template eine Familie von Funktionen bzw. Klassen: also strukturell einheitliche Konstrukte, die bzgl. der verwendeten Datentypen parametriert werden können (ggf. auf noch durch sog. Nicht-Typ-Parameter).
Template-Definitionen in Header-Dateien

Die Code-Struktierung in C++ ist ja beliebig, aber es ist üblich und praktikabel, dass Template-Definitionen in Header-Dateien geschrieben werden.

  • Die Header-Dateien brauchen wie üblich einen include-guard bzw. eine #pragma once-Direktive, um die ODR (one definition rule) sicherzustellen.

  • Die Template-Definition muss überall dort bekannt sein, wo das Template instanziiert (verwendet) wird. Die Header-Datei muss entsprechend inkludiert werden.

3.1.3. Instanziierung

Damit aus einem Template konkreter Code wird, muss es instanziiert werden. Für die Insanziierung müssen alle Template-Parameter bekannt sein. Man kann Templates immer durch direkte Angabe der Parameter explizit instanziieren. Bei Funktionstemplates kann der Compiler aber auch die Typ-Parameter selbst ermitteln (Typ-Ableitung), was zu einer impliziten Instanziierung führt.

3.1.4. Typableitung für Funktionstemplates

Die Regeln zur Template-Typ-Ableitung sind recht umfangreich. Deswegen werden wir uns hier nur mit den einfachen Fällen beschäftigen.

template<typename T> void f(P x); (1)

f(expression); (2)
1 Deklaration eines Funktionstemplates f mit dem Typ-Parameter T und einem aus T zusammengesetzten Typ P für den Parameter x (etwa const T& wie oben).
2 Aufruf der Template-Funktion mit einem Ausdruck expression (des Typs E)

Der Compiler versucht nun (für jeden Funktionsparameter getrennt), den Template-Typ-Parameter T nach einigen Regeln abzuleiten. Kommt er dabei für einen Template-Typ-Parameter zu unterschiedlichen Ergebnissen, schlägt die Kompilation fehlt.

Parameterübergabe per-reference

Hier taucht P als Referenztyp auf.

Die Regel:

  • Entferne vom Typ E von expression ggf. die Referenz &, das ergibt den Typ E'.

  • Entferne vom Typ P die Referenz &, das ergibt den Typ P'.

  • Ermittle T durch den Vergleich von P' und E' unter Anwendung der Qualifikationswandlungen, d.h. Zuweisungskompatibilität unter Beachtung der const-Qualifikation
