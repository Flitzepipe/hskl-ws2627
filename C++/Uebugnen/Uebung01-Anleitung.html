Teil 0

Terminal-Grundlagen Das Fenster, in dem Sie tippen – öffnen und navigieren

1

Das Terminal öffnen

Das Terminal ist ein Fenster, in dem Sie Befehle eintippen statt mit der Maus zu klicken. Sie öffnen es je nach Plattform so:

🪟 Windows

Windows-Taste drücken → cmd eintippen → „Eingabeaufforderung“ anklicken.

🍎 macOS

Cmd+Leertaste drücken (Spotlight-Suche) → Terminal eintippen → Enter.

🐧 Linux (Ubuntu)

Strg+Alt+T drücken – oder im Anwendungsmenü nach Terminal suchen.

✅ So sieht Erfolg aus: Ein Fenster ist offen. Ganz links steht der Eingabeprompt – ein kleiner Text, der darauf wartet, dass Sie tippen. Ab jetzt gilt: Was in den Beispielen nach dem Prompt steht, tippen Sie ein (den Prompt selbst nicht).
2

Wo bin ich gerade? – den aktuellen Ordner anzeigen

Jedes Terminal „steht“ in einem Ordner – dem aktuellen Ordner. Alle Befehle, die Sie eingeben, wirken zuerst auf diesen Ordner. Mit einem Befehl können Sie nachfragen, wo das ist:

🪟 Windows
Eingabeaufforderung — □ ✕
C:\Users\Anna> cd C:\Users\Anna

In Windows zeigt der Befehl cd ohne ZielORDNER einfach den aktuellen Ordner an.

🍎 macOS
anna@MacBook-Pro — -zsh — 80×24
anna@MacBook-Pro ~ % pwd /Users/anna

Unter macOS und Linux heißt der Befehl pwd („print working directory“).

🐧 Linux
anna@ubuntu: ~ — □ ✕
anna@ubuntu:~$ pwd /home/anna

Gleicher Befehl wie unter macOS: pwd.

✅ So sieht Erfolg aus: Es erscheint der Pfad zu Ihrem persönlichen Hauptordner („Home-Verzeichnis“) – auf Windows C:\Users\IhrName, auf macOS /Users/IhrName, auf Linux /home/IhrName.

✅ So sieht Erfolg aus: Eine Liste von Ordnern und Dateien erscheint – bei Ihnen darf sie völlig anders aussehen oder fast leer sein.
4

Einen Übungsordner anlegen

Alle Programme dieser Vorlesung sollen an einem festen Ort liegen. Legen Sie deshalb jetzt einen Ordner namens progcpp-ubungen an. Der Befehl heißt auf allen drei Plattformen gleich: mkdir („make directory“).

🪟 Windows
Eingabeaufforderung — □ ✕
C:\Users\Anna> mkdir progcpp-ubungen C:\Users\Anna>
🍎 macOS
anna@MacBook-Pro — -zsh — 80×24
anna@MacBook-Pro ~ % mkdir progcpp-ubungen anna@MacBook-Pro ~ %
🐧 Linux
anna@ubuntu: ~ — □ ✕
anna@ubuntu:~$ mkdir progcpp-ubungen anna@ubuntu:~$
✅ So sieht Erfolg aus: Der Prompt erscheint einfach wieder – ohne Meldung. Das ist hier genau richtig: Der Befehl hat funktioniert. 💡 (Stille = Erfolg, siehe Kasten oben!)
5

In den Übungsordner wechseln

Mit cd („change directory“) + Ordnername wechseln Sie hinein – auch das funktioniert auf allen Plattformen gleich:

🪟 Windows
Eingabeaufforderung — □ ✕
C:\Users\Anna> cd progcpp-ubungen C:\Users\Anna\progcpp-ubungen>
🍎 macOS
anna@MacBook-Pro — -zsh — 80×24
anna@MacBook-Pro ~ % cd progcpp-ubungen anna@MacBook-Pro progcpp-ubungen %
🐧 Linux
anna@ubuntu: ~ — □ ✕
anna@ubuntu:~$ cd progcpp-ubungen anna@ubuntu:~/progcpp-ubungen$
✅ So sieht Erfolg aus: Der Prompt hat sich verändert – er zeigt jetzt progcpp-ubungen als aktuellen Ordner an. Damit haben Sie Ihr Arbeitsverzeichnis für die ganze Vorlesung eingerichtet. 🎉
🧠 Merke – die zwei Prompt-Arten: Wenn Sie später Befehle aus Anleitungen abtippen, bedeutet das $- oder %-Zeichen (macOS/Linux) bzw. das > am Ende des Windows-Pfads: „Hier beginnt Ihre Eingabe“. Tippen Sie dieses Zeichen niemals mit ein – es ist bereits da.
Teil a

Installation prüfen & Problemlösungen Läuft der Compiler? – und was tun, wenn nicht

1

Der große Test: g++ --version

Tippen Sie den Versions-Check ein. Erscheint eine Versionsnummer, ist der Compiler installiert und das Terminal findet ihn – mehr brauchen Sie nicht.

🪟 Windows
Eingabeaufforderung — □ ✕
C:\Users\Anna> g++ --version g++ (Rev3, Built by MSYS2 project) 14.2.0
🍎 macOS
anna@MacBook-Pro — -zsh — 80×24
anna@MacBook-Pro ~ % g++ --version Apple clang version 15.0.0
🐧 Linux
anna@ubuntu: ~ — □ ✕
anna@ubuntu:~$ g++ --version g++ (Ubuntu 13.2.0-23ubuntu1) 13.2.0
✅ So sieht Erfolg aus: Eine Zeile, die mit g++ oder Apple clang beginnt und eine Versionsnummer enthält. Die genaue Nummer spielt keine Rolle – Hauptsache, es erscheint überhaupt Text.
2

Woher kommt der Befehl?

Zur Vorbereitung auf die Problemlösung: Mit einem Befehl können Sie anzeigen lassen, welche Datei hinter dem Namen g++ steckt.

🪟 Windows – where g++
Eingabeaufforderung — □ ✕
C:\Users\Anna> where g++ C:\mingw64\bin\g++.exe
🍎 macOS – which g++
anna@MacBook-Pro — -zsh — 80×24
anna@MacBook-Pro ~ % which g++ /usr/bin/g++
🐧 Linux – which g++
anna@ubuntu: ~ — □ ✕
anna@ubuntu:~$ which g++ /usr/bin/g++
✅ So sieht Erfolg aus: Eine Zeile mit einem Dateipfad. Erscheint stattdessen „Info: Could not find files“ (Windows) oder „not found“ (macOS/Linux), kennt Ihr System den Befehl noch nicht – dann hilft der Problemlösungsteil unten.

🛠️ Problemlösungen: Wenn g++ nicht gefunden wird

Der häufigste Fehler ist g++: command not found bzw. „g++“ wird nicht als Name eines Cmdlet-, Programms … erkannt. Arbeiten Sie die passenden Karten durch – fast immer löst die erste Karte das Problem:

„g++“ wird nicht erkannt / command not found – direkt nach der Installation
Das Terminal neu öffnen – die häufigste Ursache!
  • Schließen Sie das Fenster komplett und öffnen Sie ein neues
  • Grund: Das Terminal liest die Liste bekannter Programme nur beim Öffnen ein – ein frisch installiertes g++ ist im alten Fenster unsichtbar
  • Danach erneut g++ --version testen
🪟 Windows: auch nach einem neuen Fenster bleibt „wird nicht erkannt“
Installation prüfen.
  • Lief die winget-Installation mit einer Fehlermeldung durch? Dann Befehl erneut eingeben und die Meldung lesen
  • Manuelle Kontrolle: Existiert der Ordner C:\mingw64\bin mit einer g++.exe? Wenn ja, fehlt der Eintrag in den Umgebungsvariablen – wir helfen in der Übung
🍎 macOS: Der Installationsdialog erscheint nicht / bricht ab
Command Line Tools nachziehen.
  • xcode-select --install einfach erneut ausführen – Dialoge brechen beim ersten Versuch gern mal ab
  • Kommt „already installed“, war alles da: direkt g++ --version testen
🐧 Linux: „Unable to locate package“ / Paketfehler
Paketliste aktualisieren.
  • Zuerst sudo apt update ausführen, danach sudo apt install build-essential gdb erneut versuchen
  • Nicht-Ubuntu-System: Distribution prüfen (Fedora → dnf install gcc-c++)
Teil b

Hello World 🌍 Schreiben → Übersetzen → Starten → Prüfen

Jetzt schreiben Sie Ihr erstes echtes C++-Programm. Das Ziel: Der Computer grüßt Sie zurück.

1

In den Übungsordner wechseln

Das Terminal soll in Ihrem Übungsordner „stehen“ (falls es das nach Teil 0 nicht mehr tut):

🪟 Windows
Eingabeaufforderung — □ ✕
C:\Users\Anna> cd progcpp-ubungen C:\Users\Anna\progcpp-ubungen>
🍎 macOS
anna@MacBook-Pro — -zsh — 80×24
anna@MacBook-Pro ~ % cd progcpp-ubungen anna@MacBook-Pro progcpp-ubungen %
🐧 Linux
anna@ubuntu: ~ — □ ✕
anna@ubuntu:~$ cd progcpp-ubungen anna@ubuntu:~/progcpp-ubungen$
✅ So sieht Erfolg aus: Der Prompt zeigt den Übungsordner als aktuellen Ordner.
2

Das Programm schreiben – im Texteditor

Programmcode schreiben Sie in einem Texteditor – das ist wie ein ganz einfaches Word ohne Fettdruck und ohne Farbe-Buttons, das nur reinen Text speichert.

🪟 Windows: Drücken Sie die Windows-Taste, tippen Sie Editor und öffnen Sie die App „Editor“ (englisch: „Notepad“). Wer mag, installiert später Notepad++ – ein komfortablerer Editor, der C++-Code bunt einfärbt.

🍎 macOS: Öffnen Sie TextEdit aus dem Programmordner. Wichtig: Stellen Sie sofort im Menü Format → „Mit reinem Text beginnen“ um – TextEdit kann sonst Formatierungen speichern, die den Compiler stören.

🐧 Linux: Öffnen Sie gedit („Texteditor“) aus dem Anwendungsmenü.

Tippen Sie exakt diesen Code ab:

1#include <iostream> // Bibliothek für Ein-/Ausgabe 2 3int main() { 4 std::cout << "Hello, World!" << std::endl; 5 return 0; // Programm erfolgreich beendet 6}
📖 Was passiert hier Zeile für Zeile?
  • #include <iostream> – lädt die Bibliothek für Ein- und Ausgabe dazu
  • int main() { ... } – das ist die Stelle, an der jedes C++-Programm startet (der „Startpunkt“)
  • std::cout << ... – bedeutet: „drucke das Folgende auf den Bildschirm“
  • std::endl – macht einen Zeilenumbruch danach
  • return 0; – meldet dem System: „Ich bin fehlerfrei fertig“ (0 = alles gut)

Tipp: Abtippen statt Kopieren! So merken Sie sich die Schreibweise am ehesten. Achten Sie auf Groß-/Kleinschreibung und die Semikolons (;) am Zeilenende.

3

Speichern als hello.cpp – und zwar im Übungsordner!

🪟 Windows (Editor): Menü „Datei → Speichern unter“. Wechseln Sie links zu Dokumente? Nein – navigieren Sie zu C:\Users\IhrName\progcpp-ubungen. Wichtig: Bei „Dateityp“ wählen Sie „Alle Dateien (*.*)“, sonst hängt Windows heimlich ein .txt an und Ihre Datei heißt hello.cpp.txt. Dateiname: hello.cpp → Speichern.

🍎 macOS (TextEdit): Ablage → Sichern. Name: hello.cpp. Falls ein Dialog fragt, ob Sie wirklich die Endung „.cpp“ verwenden wollen → „.cpp verwenden“ anklicken. Speicherort: Ihr Übungsordner (/Users/IhrName/progcpp-ubungen).

🐧 Linux (gedit): Speichern-Button → Ordner progcpp-ubungen in Ihrem persönlichen Ordner wählen → Dateiname hello.cpp → Speichern.

4

Kontrolle im Terminal: Ist die Datei wirklich da?

🪟 Windows – dir
Eingabeaufforderung — □ ✕
C:\Users\Anna\progcpp-ubungen> dir Verzeichnis von C:\Users\Anna\progcpp-ubungen 14.10.2026 10:42 132 hello.cpp
🍎 macOS – ls
anna@MacBook-Pro — -zsh — 80×24
anna@MacBook-Pro progcpp-ubungen % ls hello.cpp
🐧 Linux – ls
anna@ubuntu: ~/progcpp-ubungen — □ ✕
anna@ubuntu:~/progcpp-ubungen$ ls hello.cpp
✅ So sieht Erfolg aus: hello.cpp steht in der Liste. Sehen Sie statt dessen hello.cpp.txt oder gar nichts? Dann hat der Editor woanders oder unter falschem Namen gespeichert – öffnen Sie den Speichern-Dialog noch einmal (Schritt 3) und achten Sie auf Ordner und Dateityp.
5

Übersetzen – aus dem Text wird ein Programm

Mit einem Befehl wandeln Sie den Quelltext in ein ausführbares Programm um. Achtung, ein kleiner plattformbedingter Unterschied im Ergebnisnamen: Windows macht hello.exe, macOS/Linux macht hello.

🪟 Windows
Eingabeaufforderung — □ ✕
C:\Users\Anna\progcpp-ubungen> g++ -o hello.exe hello.cpp C:\Users\Anna\progcpp-ubungen> dir 14.10.2026 10:42 132 hello.cpp 14.10.2026 10:45 172.032 hello.exe
🍎 macOS
anna@MacBook-Pro — -zsh — 80×24
anna@MacBook-Pro progcpp-ubungen % g++ -o hello hello.cpp anna@MacBook-Pro progcpp-ubungen % ls hello hello.cpp
🐧 Linux
anna@ubuntu: ~/progcpp-ubungen — □ ✕
anna@ubuntu:~/progcpp-ubungen$ g++ -o hello hello.cpp anna@ubuntu:~/progcpp-ubungen$ ls hello hello.cpp
✅ So sieht Erfolg aus: Der Compiler druckt gar nichts – und genau das ist gut (Stille = Erfolg!). Mit dir bzw. ls sehen Sie die neu entstandene Datei: hello.exe (Windows) bzw. hello (macOS/Linux).
📖 Was bedeuten die drei Teile des Befehls? g++ = „lieber Compiler, übersetze …“ · -o hello(.exe) = „… und nenne das fertige Programm so“ · hello.cpp = „… und benutze dabei diese Textdatei als Vorlage“.
6

Starten!

Auf Windows starten Sie das Programm, indem Sie den Namen eintippen. Auf macOS und Linux müssen ein Punkt und ein Schrägstrich davor – das bedeutet „such das Programm genau hier im aktuellen Ordner“:

🪟 Windows
Eingabeaufforderung — □ ✕
C:\Users\Anna\progcpp-ubungen> hello.exe Hello, World!
🍎 macOS
anna@MacBook-Pro — -zsh — 80×24
anna@MacBook-Pro progcpp-ubungen % ./hello Hello, World!
🐧 Linux
anna@ubuntu: ~/progcpp-ubungen — □ ✕
anna@ubuntu:~/progcpp-ubungen$ ./hello Hello, World!
✅ So sieht Erfolg aus: Die Zeile Hello, World! erscheint – Ihr erstes C++-Programm läuft! 🎉 Das ist der Moment, in dem aus purem Text ein lebendiges Programm geworden ist.
📖 Warum ./ auf macOS/Linux? Diese Systeme suchen Programme nur in fest hinterlegten Systemordnern – nicht im Ordner, in dem Sie gerade stehen. ./ heißt wörtlich: „nimm die Datei aus genau diesem Ordner hier“. Vergisst man die zwei Zeichen, kommt „command not found“, obwohl die Datei existiert. (Windows ist hier einfacher: Es sucht automatisch im aktuellen Ordner mit.)
7

Prüfen: Hat das Programm „alles gut“ gemeldet?

Ihr Programm endet mit return 0; – das ist eine Rückmeldung ans System: „Ich bin ohne Fehler durchgelaufen“. Diese Zahl können Sie sich anzeigen lassen – ein kleines Testwerkzeug, das wir öfter nutzen werden:

🪟 Windows – echo %errorlevel%
Eingabeaufforderung — □ ✕
C:\Users\Anna\progcpp-ubungen> hello.exe Hello, World! C:\Users\Anna\progcpp-ubungen> echo %errorlevel% 0
🍎 macOS – echo $?
anna@MacBook-Pro — -zsh — 80×24
anna@MacBook-Pro progcpp-ubungen % ./hello Hello, World! anna@MacBook-Pro progcpp-ubungen % echo $? 0
🐧 Linux – echo $?
anna@ubuntu: ~/progcpp-ubungen — □ ✕
anna@ubuntu:~/progcpp-ubungen$ ./hello Hello, World! anna@ubuntu:~/progcpp-ubungen$ echo $? 0
✅ So sieht Erfolg aus: Eine 0 – genau die Zahl aus return 0;. Damit ist der komplette Kreislauf gelaufen: schreiben → übersetzen → starten → prüfen. Diesen Kreislauf werden Sie in dieser Vorlesung hunderte Male drehen.
Teil c

Einen Fehler absichtlich auslösen 💥 Fehlermeldungen lesen lernen – die wichtigste Fertigkeit des Semesters

Früher oder später schreibt jeder fehlerhaften Code. Wer Fehlermeldungen lesen kann, ist in Minuten fertig – wer davor zurückschreckt, in Stunden. Deshalb üben wir das Lesen jetzt ganz gezielt, indem Sie selbst einen Fehler einbauen.

1

Fehler einbauen: ein Semikolon löschen

Öffnen Sie hello.cpp im Editor und löschen Sie das Semikolon am Ende der std::cout-Zeile. Die Zeile sieht dann so aus:

4 std::cout << "Hello, World!" << std::endl ▏← hier fehlt das Semikolon!

Speichern Sie die Datei (im Editor!).

2

Neu übersetzen – und die Fehlermeldung betrachten

Führen Sie denselben Übersetzungsbefehl wie in Teil c aus. Diesmal wird der Compiler nicht still sein:

🪟 Windows
Eingabeaufforderung — □ ✕
C:\Users\Anna\progcpp-ubungen> g++ -o hello.exe hello.cpp hello.cpp: In function 'int main()': hello.cpp:5:12: error: expected ';' before 'return' 5 | return 0; | ^ | ; compilation terminated.
🍎 macOS
anna@MacBook-Pro — -zsh — 80×24
anna@MacBook-Pro progcpp-ubungen % g++ -o hello hello.cpp hello.cpp:5:12: error: expected ';' before 'return' 5 | return 0; | ^ | ; 1 error generated.
🐧 Linux
anna@ubuntu: ~/progcpp-ubungen — □ ✕
anna@ubuntu:~/progcpp-ubungen$ g++ -o hello hello.cpp hello.cpp:5:12: error: expected ';' before 'return' 5 | return 0; | ^ | ; compilation terminated.
📖 Die Fehlermeldung Stück für Stück entziffern (sie ist auf allen Plattformen fast gleich aufgebaut):
  • hello.cpp:5:12: → in dieser Datei, Zeile 5, Spalte 12 ist der Compiler gestolpert
  • error: expected ';' before 'return' → was fehlt: ein Semikolon, und zwar vor dem Wort return
  • darunter zeigt der Compiler die betroffene Zeile im Quelltext, markiert die Stelle mit ^ und schlägt sogar die Korrektur vor (das einsame ;)

🤔 Kuriosität zum Nachdenken: Gelöscht haben Sie in Zeile 4 – angemeckert wird Zeile 5! Der Compiler stolpert nämlich erst am nächsten Wort über die Lücke. Daraus folgt eine wichtige Regel: Ist die angemeckerte Zeile fehlerfrei, prüfen Sie die Zeile darüber!

3

Reparieren – und den Beweis antreten

Setzen Sie das Semikolon in der std::cout-Zeile wieder ein, speichern Sie im Editor – und drehen Sie den kompletten Kreislauf noch einmal:

🪟 Windows
Eingabeaufforderung — □ ✕
C:\Users\Anna\progcpp-ubungen> g++ -o hello.exe hello.cpp (keine Ausgabe = gut!) C:\Users\Anna\progcpp-ubungen> hello.exe Hello, World! C:\Users\Anna\progcpp-ubungen> echo %errorlevel% 0
🍎 macOS
anna@MacBook-Pro — -zsh — 80×24
anna@MacBook-Pro progcpp-ubungen % g++ -o hello hello.cpp (keine Ausgabe = gut!) anna@MacBook-Pro progcpp-ubungen % ./hello Hello, World! anna@MacBook-Pro progcpp-ubungen % echo $? 0
🐧 Linux
anna@ubuntu: ~/progcpp-ubungen — □ ✕
anna@ubuntu:~/progcpp-ubungen$ g++ -o hello hello.cpp (keine Ausgabe = gut!) anna@ubuntu:~/progcpp-ubungen$ ./hello Hello, World! anna@ubuntu:~/progcpp-ubungen$ echo $? 0
✅ So sieht Erfolg aus: Übersetzen ohne Meldung, Start mit Ausgabe, Rückgabewert 0. Sie haben gerade einen Fehler gefunden, die Meldung gelesen, gedeutet und behoben – genau dieses Vorgehen werden Sie in dieser Vorlesung ständig brauchen.
🧠 Umgang mit Fehlermeldungen – die 4 goldenen Regeln:
  1. Von oben nach unten lesen – die erste Zeile mit error: ist fast immer die Ursache, alles darunter oft nur Folgeprobleme.
  2. Immer nur den ersten Fehler beheben, dann neu übersetzen – oft verschwinden mehrere Meldungen mit einem einzigen Fix (Kettenfehler!).
  3. „Datei:Zeile:Spalte“ ernst nehmen – die Meldung sagt Ihnen genau, wo Sie suchen müssen. Und: Ist die gemeldete Zeile sauber, schauen Sie in die Zeile davor.
  4. Ruhe bewahren – Fehler sind Alltag beim Programmieren, kein Versagen. Niemand schreibt fehlerfreien Code beim ersten Versuch – auch Ihre Dozenten nicht.
🎯 Zusatzaufgabe: Bauen Sie weitere Fehler ein – immer nur einen auf einmal, beobachten, zurückbauen: (1) tippen Sie cout statt std::cout – (2) löschen Sie die Anführungszeichen um Hello, World! – (3) nennen Sie main in Main um. Vergleichen Sie: Wie unterscheiden sich die Meldungen?
